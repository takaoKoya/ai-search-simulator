# 03 — Autonomy Maturity Audit

Scale (as specified for this audit):
- **LEVEL 0 — Manual**: a human does the work; software only records it.
- **LEVEL 1 — AI Assist**: AI produces a draft/suggestion; a human does everything else (trigger, judge, act).
- **LEVEL 2 — Task Automation**: AI executes a fixed, pre-authored multi-step task end-to-end once triggered, but does not choose *whether/what* to do next on its own, and does not act externally without a human approval gate.
- **LEVEL 3 — Conditional Autonomy**: AI acts (including externally) within pre-set rules/limits without a human approval per instance, for at least some class of action.
- **LEVEL 4 — Goal-driven Autonomy**: AI decomposes a Goal into work and decides what to do next based on Goal/KPI gap, without a human re-triggering each step.
- **LEVEL 5 — Closed-loop Company Autonomy**: the full Observe→Think→Decide→Plan→Act→Verify→Learn→Observe loop runs continuously against Goals/Budget/Authority, with humans only at Escalation points.

Every rating below is evidence-based (see `05_AGENT_RUNTIME_AUDIT.md` and `06_EVENT_TRIGGER_SCHEDULER_AUDIT.md` for full citations), not a vibe.

| Dimension | Level | Why |
|---|---|---|
| **Planning** | **1–2** | No graph, node, or provider call decomposes a Goal into Objective→Project→Work→Task→Action. All 18 LangGraph pipelines have a fixed, hardcoded node sequence (`.addEdge`), authored by a human developer once. The only "decision" points are deterministic comparisons (score threshold, critic PASS/FAIL, missing-precondition checklist) — never an LLM/agent choosing between multiple candidate plans. This is Task Automation at best; it does not reach Conditional Autonomy because even the deterministic branches never result in an unsupervised *external* action. |
| **Execution** | **2** | Once triggered, a graph runs its fixed steps to completion automatically (research → draft → score, etc.), including real external calls in 2 cases (Gmail send, Calendar event create) — but every external/irreversible action is gated by an explicit human approval or a separate human-only route (`assertRole(APPROVER_ROLES)` on send/deliver/confirm routes). Internal-only steps run unattended; anything client-facing does not. |
| **Verification** | **2** | 12 of 18 graphs have an explicit critic/QA node before allowing an approval to be created; 2 of those (`salesOutreachPrep`, `proposalDraft`) use real hand-written deterministic rule-checkers (DNC hard-block, margin-rate/unmatched-service checks, a proposal↔estimate "Reconciliation Engine"). The rest use the *same* deterministic `TemplateProvider` to grade its own output — not an independent evaluator. 5 graphs (meeting scheduling/prep/minutes, negotiation analysis) have no critic/QA node at all and mark themselves "completed" on write. No LLM-based judge exists anywhere (there is no LLM at all). |
| **Retry** | **1** | The only retry mechanism in the entire runtime is a fixed regenerate-the-same-step loop, capped at 3 attempts, driven by the critic verdict (`decideCriticVerdict`), present in 5 of 18 graphs. There is zero retry of infrastructure failures (every Supabase call does `if (error) throw`, no backoff), zero alternative-tool fallback, and zero automated human escalation on failure — a thrown error simply marks `workflow_runs.status = 'failed'` and stops. |
| **Scheduling** | **0 (as deployed) / 2 (as coded)** | Four real, tested cron routes exist (`sla-check`, `followup-check`, `token-refresh`, `growth-loop-check`) with a genuine overlap-safe Postgres lock (`background_jobs`). **But no `vercel.json` or any other in-repo scheduler configuration exists**, and no npm script or CI job calls them either. As currently committed, nothing in this repository ever calls these routes — they are dormant HTTP endpoints. The code is capable of Task-Automation-level scheduled execution; the *system as deployed* is at Level 0 for this dimension until an external scheduler is wired up. |
| **Event Response** | **0** | ~60 event types are defined (`lib/office/eventTypes.ts`) and every write to `agent_events` is real, but **nothing in the codebase subscribes to an event type and reacts to it** — every read site is a UI activity-feed query. No Supabase Realtime usage exists anywhere in the repo. The one process that looks event-driven (renewal checking anomalies) is a direct table read within the same graph run, not a subscription. |
| **Goal Management** | **1** | A `goals` table exists, but it is foreign-keyed to `project_id` only — there is no tenant/company-level Goal, and no graph or route was found that reads the `goals` table to decide what work to generate next. Goals are recorded data, not an autonomy input. |
| **KPI Response** | **2–3** (best-performing dimension) | This is the one place a measured gap causes an automatic downstream action without additional human input: `measurement_graph` evaluates KPI effect (SUCCESS/PARTIAL/NEGATIVE/…); a NEGATIVE or PARTIAL_SUCCESS result automatically feeds `renewal_graph`'s upsell-detection step, which can create an `upsell_opportunities` row with no human step in between *within that one cron/manual invocation*. This reaches toward Conditional Autonomy — but it stops there: creating the candidate still requires human approval before anything happens, and the whole chain only executes if something first calls `measurement_graph` (currently only a human button or an unscheduled cron route). |
| **Multi-Agent** | **1** | No graph or node ever calls another agent/graph directly; "handoffs" between named agents within one graph are `agent_events` rows narrating that a conceptual handoff happened, not a function call from Agent A into Agent B. All real cross-*graph* coordination goes through DB state (an `approval_requests` row) plus a human decision. This is closer to a single-actor scripted pipeline wearing multiple name tags than true multi-agent delegation. |
| **Learning** | **1** | `decision_memories` genuinely persists human rejection reasons, and `maybeFlagRuleCandidate` computes a real same-industry-repeat heuristic over the last 30 — but this is never read back into any `provider.generate()` call. No graph or prompt becomes different tomorrow because of what happened today. This is an audit log with one human-facing nudge, not a learning loop. |
| **Cost Control** | **1** | `ai_cost_yen` accumulates per lead/opportunity (a real running total), but nothing anywhere compares it to a limit, and no route throttles repeated invocation. Tracked, not controlled. |
| **Escalation** | **1** | `sla-check` computes a real ON_TRACK/DUE_SOON/BREACHED label from business-hours-aware due dates — but only writes the label; nothing pages, emails, reassigns, or otherwise acts on a breach. Escalation is visible in the UI if a human happens to look, never pushed. |

## 3.1 Composite read (not a single score, per the audit brief's own instruction)

No dimension in this system reaches Level 3 in practice (as deployed). KPI Response and Execution are the most mature (solid Level 2, with KPI Response touching Level 3 in its internal chaining). Scheduling and Event Response are functionally Level 0 today despite having Level-2-capable code sitting unused. Retry, Goal Management, Learning, Cost Control, and Escalation are all Level 1 — data is tracked or a narrow mechanism exists, but nothing acts on it autonomously.

## 3.2 The single sentence that matters most

**Every dimension of this system tops out at "the AI does a lot of correct, verifiable work once a human (or an unwired cron route) starts it" — none reach "the AI decides on its own that work needs to happen."** That is the precise, evidence-backed boundary between where this system is today and Level 4 (Goal-driven Autonomy), and it is the subject of `14_ROOT_CAUSE_ANALYSIS.md`.
